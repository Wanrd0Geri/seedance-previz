# 代理体规范

函数都在 `scripts/previz_lib.py`，下文 `pv.` 开头。单位米，Z 向上。

## 1 躯体代理

```python
pv.torso_proxy("CHR_猿三_图1", height=2.9, color=(0.80, 0.78, 0.74), face_dir=(0, -1, 0), loc=(0, 145, 92.4), head_ratio=1/5)
```

- 组成：胶囊躯干 + 头球 + 嘴部小球，没有四肢。为什么：粗白模带四肢会僵，官方最佳实践是只留躯体。
- 坐姿：`pose="sit"`，躯干矮一截，加一块合在一起的腿部 `_Lap`，不做两条腿（用户偏好）。坐着的人要站起来：另建一个站姿代理，`pv.stand_up(坐, 站, f0)` 从坐的位置边起边让到站的位置；换代理那一下有跳变，交接卡写"真实动作是连贯起身"。
- 身高按角色设定。头身比默认 1/7；猿类、Q 版改 `head_ratio=1/5` 到 `1/4`，要一眼分得出头和身子。
- 朝向：嘴部小球 = 脸朝的方向。`face_dir` 写世界方向，默认 -Y。
- 根物体是空物体，原点在脚底；键根物体就是让整个角色走位。子物体叫 `_Body`、`_Head`、`_Muzzle`。
- 真要手臂动作（比如巨掌压镜）：只加那一条胳膊，提示词写全这条胳膊的动作序列，交接卡注明（自查 ②）。
- 主观看手的镜头：一双手（掌 + 指的小几何体）挂在那一镜的相机上，只在那一镜可见（hide_render 键），同一镜把本人藏起来（相机在他头里）。名字用 `POV_`，别带 hand。

## 2 颜色

- 默认中性灰阶或近服装色，饱和度 ≤0.3。饱和度 = (最大 − 最小) ÷ 最大，按写进去的 RGB 三个数算。为什么：白模颜色会渗进成片（外部实测）。用户指定鲜明分色（红橙黄绿蓝，一眼分清谁是谁）就照做，`ce.run(vivid=True)`，交接卡写"服装颜色以参考图为准"。E02S08 用鲜明色一次成片没串色（一次观察，没对照过）。
- 角色之间靠明度区分：明度拉开到一眼能分（起步值差 0.15 以上，看渲染再调）。
- 颜色 → 图N 写进任务卡和交接卡；颜色词要能直接放进映射句。
- 参考值：

| 用途 | RGB | 饱和度 |
|---|---|---|
| 暖灰（肤色、布衣） | (0.55, 0.50, 0.45) | 0.18 |
| 近白（白毛、白衣） | (0.80, 0.78, 0.74) | 0.08 |
| 冷灰（盔甲、铁器） | (0.45, 0.48, 0.52) | 0.13 |
| 深灰（黑衣、深色兽） | (0.25, 0.25, 0.27) | 0.07 |
| 浅灰金（金色法相） | (0.80, 0.74, 0.60) | 0.25 |
| 中灰（地面、台阶） | (0.50, 0.50, 0.50) | 0 |

## 3 命名

- 角色：`CHR_<角色>_<图N>`，如 `CHR_苏云_图1`。check_export 靠 `CHR_` 前缀找角色。
- 场景 `ENV_`，道具 `PRP_`，相机 `CAM_`（`RIG_`、`HEAD_`、`AIM_` 自动生成），主光 `LGT_sun`。
- 子物体名别带 `_Arm`、`_Leg`、`_Wing`、`_Hand`、`_Foot`：check_export 按名字认四肢。中文只在整段名就是四肢词（臂、左腿、翅膀……）时才算，"展臂法相""盘腿座"不算，`_Lap` 不算。
- 本库建的东西都进 `PREVIZ` 集合。重跑同名函数会替换本库之前建的物体；同名物体不在这个集合里，函数直接报错，不覆盖用户的东西。

## 4 场景几何

- 建筑：`pv.mk_box` 做台基和墙身。原点在底面，loc 写落地点。
- 屋顶：`pv.roof(name, width, depth, height, loc)`，四坡顶，底面在檐口高度；出檐就把宽深放大；方形底面自动变攒尖。
- 飞檐翘角：屋角放一个小方块斜着翘起，加一个屋脊兽小块（猿三案例的前景飞檐就是这样）。
- 多层塔楼：方块和屋顶逐层缩小往上叠。
- 台阶：`pv.stairs(name, width, run, rise, steps, loc)`，整段合成一个物体，默认朝 +Y 往上走，原点在第一级前沿底边中点。
- 地面、平台：大方块。地形起伏：压扁的球。
- 云：`pv.mk_sphere(name, radius, loc, color, scale=(2, 1, 0.2))`；要撕开的云拆成左右两块，各自键位移。
- 巨物：按真实比例，不缩。尺度靠参照物读出来：台阶、殿宇、塔楼、人。

## 5 主光

- 一盏 `LGT_sun`，由 `pv.setup_workbench(sun_dir=...)` 建。sun_dir 写"光从哪来"的世界方向，z >0。
- Workbench 不认灯物体：投影方向写在 `scene.display.light_direction`，摄影棚光转到同一方位，setup_workbench 都办了（换算见 export-verify.md 第 1 节）。LGT_sun 用来记录光向，切 EEVEE 时直接可用。
- 渲染用 Workbench 摄影棚光（世界坐标）+ 物体色 + 投影。要纯平光传 `light="FLAT"`，形体会变平。
- 逆光时角色正面很暗，这是对的：光向要和成片一致。

## 6 世界坐标习惯

- 先定"前"是哪个方向，写进任务卡。猿三案例：石阶从 y=0 往 +Y 爬到主殿，宫城正面朝 -Y。
- 角色正面 = 本地 -Y。

## 7 特效

- 光带（人化作一道流光飞来）：`path = pv.light_stream("FX_光流", [(60, 64, 7), (38, 26, 15), (6, 3.5, 13.5), 落点], f_start=20, f_arrive=160)`。两根曲线管带拖尾 + 头部小球，模型读得懂（E02S08 成片有彗星状流光、收拢成人）。角色看光：`path.head(f)`。
- 从无到有显形：`pv.reveal(root, 150, 198)`——之前隐藏，之后透明度 0 → 1。只用于"从无到有"；变淡、缥缈、飘散不在白模里做，交给提示词（用户 2026-09-27）。
- 特效颜色饱和度高属正常，check_export 报环境色警告就写进交接卡的映射句（handoff-card.md）。
